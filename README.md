# wize-site

合同会社WIZE のコーポレートサイト（www.wize.uno）。
ペライチで運用していた3ページ（トップ／.note／セミナー）を、GitHub Pages で公開できる静的サイトへ移行したものです。

デザインは `fairfee_lp_4.html`（フェアフィー・プロジェクト）と同じデザイントークン（藍・紙・墨・朱／明朝＋ゴシック＋等幅）を使い、2つのサイトが同じ「家族」に見えるようにしています。

---

## 1. 構成

```
index.html            トップページ
note/index.html       .note（バックナンバー一覧）
seminar/index.html    セミナー一覧
admin/index.html      管理画面（掲載内容の編集）
404.html              旧URLからの誘導つきエラーページ

assets/css/site.css   デザイントークンと全ページ共通のスタイル
assets/js/site.js     共通処理（JSON読み込み・ヘッダー/フッター・下書き反映）
assets/js/page-*.js   各ページの組み立て
assets/img/note/      .note の記事サムネイル（ペライチから取り込み済み）

content/site.json     ヘッダー・フッター（全ページ共通）
content/admin.json    管理画面のログイン設定
content/home.json     トップページの掲載内容
content/note.json     .note の記事93件／年別バックナンバー155件
content/seminar.json  セミナーの掲載内容

admin/auth.js         管理画面のログイン処理
assets/js/admin-inline.js  .note ページ上での編集モード（管理者のみ読み込まれる）
tools/                移行スクリプトと、HTML書き出し・Apps Script
```

**掲載内容はすべて `content/*.json` にあります。** HTMLは器で、文言・記事・リンクはJSONを読んで組み立てています。
だから管理画面からJSONだけを更新すれば、サイトが更新されます。

3つのHTMLには、JSONから組み立てた結果を**あらかじめ焼き付けて**あります（`<!--wize:page:start-->` などのマーカーの間）。
JavaScriptを実行しない検索エンジンにも記事が読まれるようにするためで、ブラウザではその上からJavaScriptが同じ内容を描き直します。

> **注意：** 管理画面の「GitHubへ公開」が更新するのは `content/*.json` だけです。
> 表示は常に最新になりますが、焼き付けたHTMLは古いままになります。
> 検索エンジン向けにも最新化したいときは、`npm run export:inplace` を実行してコミットしてください（何度実行しても同じ結果になります）。

## 2. ローカルで確認する

`fetch()` を使うため、ファイルを直接開く（file://）と動きません。簡易サーバー経由で開いてください。

```bash
node tools/serve.mjs
```

- サイト → http://localhost:4173/
- .note → http://localhost:4173/note/
- セミナー → http://localhost:4173/seminar/
- 管理画面 → http://localhost:4173/admin/

止めるときは `Ctrl + C`。ポートを変えたいときは `node tools/serve.mjs --port 8080`。

Node に最初から入っている機能だけで動くので、`npx` も `npm` も使いません。
**PowerShell で `npx` が「スクリプトの実行が無効になっている」と出る環境**でも、これなら動きます
（`node.exe` は PowerShell スクリプトではないため、実行ポリシーの対象外です）。

本番と同じく、存在しないURLには `404.html` を返します。

## 3. 管理画面の使い方

**入口はフッター右下の「管理」リンク**です（全ページの最下部にあります）。
URLで開く場合は http://www.wize.uno/admin/ 、ローカルでは http://localhost:4173/admin/ です。

> **ファイルを直接ダブルクリックして開くと動きません。** ブラウザが `content/*.json` の読み込みを
> 禁止するためです（`file://` の制限。設定では変えられません）。
> 手元で確認するときは、必ず「2. ローカルで確認する」のサーバー経由で開いてください。
> 直接開いた場合は、その旨と開き方を画面に表示します。

フッターの「管理」リンクを消したいときは、`content/site.json` の `footer.adminLink` を `false` にしてください。
ただしURLを隠しても守りにはなりません。守っているのはパスワードと、公開に必要なGitHubトークンです。

1. 上部のタブで編集する対象を選ぶ（共通設定／トップ／.note／セミナー）
2. 項目を書き換える。入力するとこのブラウザに**下書き**として自動保存されます
3. 「プレビュー」を押すと、下書きが反映された状態でサイトを確認できます
   （プレビュー中は右下に朱色のバッジが出ます。実際の公開サイトには反映されていません）
4. 「GitHubへ公開」で本番へ反映します

### 管理画面にパスワードをかける

パスワードは **Googleスプレッドシートで管理**します。コードを触らずに、シートを書き換えるだけで追加・変更・停止ができます。

シートは次の形にしてください（見出しの文字が「名前」「パスワード」「有効」を含んでいれば、列の順番は自由です）。

| 名前 | パスワード | 有効 |
|---|---|---|
| 和田 | ******** | TRUE |
| スタッフ | ******** | TRUE |
| 退職者 | ******** | FALSE |

`有効` が `FALSE` `×` `無効` などの行は、パスワードが合っていても通しません。

照合のしかたは2通りあります。**方法Aを推奨します。**

#### 方法A：Apps Script に照合させる（推奨）

パスワードはGoogle側だけで突き合わされ、シートの中身はサイトに出てきません。

1. パスワード管理用のスプレッドシートで **拡張機能 → Apps Script** を開く
2. `tools/gas-auth.gs` の中身をすべて貼り付け、`SHEET_NAME` を実際のシート名に変える
3. **デプロイ → 新しいデプロイ → ウェブアプリ**
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**（これでないと管理画面から届きません）
4. 発行されたURLを `content/admin.json` の `gasEndpoint` に貼る

> 「全員」はこのURLを叩けるという意味で、シートが誰でも見られるという意味ではありません。このスクリプトは合致したかどうかしか返しません。

#### 方法B：公開CSVを読む（簡単だが弱い）

1. スプレッドシートで **ファイル → 共有 → ウェブに公開** を選び、形式を **カンマ区切り（.csv）** にする
2. 発行されたURLを `content/admin.json` の `sheetCsvUrl` に貼る

> **この方法では、URLを知っている人はパスワードを読めてしまいます。** 手軽さと引き換えである点をご承知おきください。

#### 設定できるまでの間

`content/admin.json` の `"enabled"` を `false` にすると、パスワードなしで管理画面を開けます。
この状態でも、一度 `/admin/` を開いておけば `/note/` の編集モードは使えます。

#### この鍵でできること・できないこと

**静的サイトなので、この画面はあくまで入口の鍵です。** ブラウザの開発者ツールを使える人は、表示そのものは回避できます。
ただし**サイトを実際に書き換えるにはGitHubのアクセストークンが別途必要**で、そちらが本当の防御になっています。
パスワードは「関係者以外がうっかり触らないようにする」ためのものと考えてください。

一度ログインすると `sessionHours`（初期値12時間）の間は再入力を求めません。管理画面と `/note/` の編集モードで同じログインを使うため、別タブで開いても入力し直す必要はありません。共用パソコンでは、離席前に「ログアウト」を押してください。

### .note のページ上で直接編集する

管理者としてログインした状態で `/note/` を開くと、画面下に操作バーが出ます。
**「編集モード」をオンにすると、記事とメールマガジンのバックナンバーをその場で編集できます。**

- カードにマウスを乗せると **編集 / ↑ / ↓ / 複製 / 削除** が出ます
- 分野ごとに「＋ この分野に記事を追加」、年別バックナンバーに「＋ この年に号を追加」
- 「サイトに表示する」を外した項目は、編集モード中だけ朱色の「非公開」付きで表示されます
- 絞り込みや検索で目的の記事を探してから編集できます

変更は管理画面と同じ下書きに入ります。**実際のサイトに反映するには、バーの「管理画面で公開する」から「GitHubへ公開」してください。**
「下書きを破棄」で編集前に戻せます。

> ログインしていない閲覧者には、編集用のスクリプト自体が読み込まれません。

### 「GitHubへ公開」に必要なもの

GitHub の **fine-grained personal access token**（対象リポジトリに対して `Contents: Read and write`）。

1. GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token
2. Repository access でこのリポジトリだけを選択
3. Permissions → Repository permissions → **Contents: Read and write**
4. 発行されたトークンを管理画面の公開ダイアログに貼り付ける

「このブラウザにトークンを保存する」にチェックを入れると次回から入力不要になります。
共用パソコンでは**チェックを外して**ください。

### トークンを使わない運用

「JSONを書き出す」で変更した JSON ファイルをダウンロードし、`content/` に上書きして git commit / push しても同じ結果になります。

### HTMLを書き出す

「HTMLを書き出す」を押すと、**編集中の内容を埋め込んだ完成HTML**をZIPでダウンロードできます。書き出し方を2つから選べます。

| | 中身 | 使いどころ |
|---|---|---|
| **サイト用** | `index.html` / `note/index.html` / `seminar/index.html`。CSS・画像は `assets/` を参照 | リポジトリの同じ場所へ上書きして公開する。中身がHTMLに焼き付くので、JavaScriptを実行しない検索エンジンにも記事が読まれる |
| **単体HTML** | `home.html` / `note.html` / `seminar.html`。CSS・JavaScript・掲載内容・画像をすべて1ファイルに埋め込み | ダブルクリックで開ける。メール添付、印刷、他サーバーへの単体設置、内容確認用のスナップショット |

- 単体HTMLはネット接続なしでも表示できます（Webフォントだけは取得できないため、代替書体で表示されます）。
- `.note` は記事画像209枚をすべて含むため、単体HTMLでは11MB前後になります。
- 単体HTML同士のリンクは、同時に書き出したページ同士でつながります。書き出さなかったページへのリンクは公開サイト（`content/site.json` の `brand.siteUrl`）へ向きます。
- **どちらの書き出しも、HTMLに焼き付けたうえで元のJavaScriptも読み込みます。** 検索エンジンにはHTMLがそのまま読まれ、ブラウザでは従来どおり絞り込みや検索が動きます。

書き出しには数秒かかるため、その頃にはクリック操作から離れており、ブラウザによっては自動ダウンロードが無視されます。
そのため完了後に**「ZIPをダウンロード」ボタン**が出ます。自動で保存されなかった場合はそれを押してください。

### ブラウザを使わずに書き出す

ダウンロードがうまくいかない環境では、コマンドで直接ファイルへ書き出せます。管理画面と同じ結果になります。

```bash
npm run export:html         # dist/site/ へ（assets を参照するページ）
npm run export:standalone   # dist/standalone/ へ（1ファイル完結）
npm run export:inplace      # リポジトリ内のHTMLを直接更新する
```

`--pages home,note` のように対象を絞ることもできます。

### 更新のしかた

- **掲載内容だけ変える** … 管理画面の「GitHubへ公開」。リポジトリ欄には
  `DrPotter2022/call-link-test`、ブランチは `main` を入れます。
- **HTMLやCSSも変える** … このフォルダで編集し、`npm run export:inplace` を実行してから
  `call-link-test` へ反映します（`git remote` に `publish` として登録済み）。

apex（`wize.uno`）は現在もペライチを向いており、旧サイトが動いています。
そちらを止めるかどうかは別途ご判断ください。

## 5. ペライチからの移行スクリプト（`tools/`）

すでに実行済みで、結果は `content/*.json` と `assets/img/note/` に入っています。
やり直したいときだけ使ってください。

```bash
node tools/scrape-peraichi.mjs        # 3ページを取得し tools/.cache/*.raw.json を作る
node tools/build-content.mjs --force  # note.json を作り直し、画像を取り込む
node tools/optimize-images.mjs        # 画像を幅640px/WebPへ（74MB → 4.3MB）
```

`--force` は `content/note.json` を上書きします。管理画面での編集内容が消えるので注意してください。

## 6. 既知の申し送り

- **フッターの法務ページ2本（プライバシーポリシー・決済に関する利用規約）は、まだペライチ上のURLを指しています。** ペライチを解約する前に、このサイト内へ移す必要があります。
- **事業者情報（OPERATOR — 運営）と特定商取引法に関する表記へのリンクは、フッターから削除しました。** 決済はUdemy側で完結し、特商法の表記もUdemy側にあるためです。復活させる場合は `content/site.json` の `footer` に `company`（`name` / `representative` / `address` / `email` / `tel` / `hours`）を書き戻してください。値が入っていれば自動で表示されます。
- **★ `www.wize.uno` は既に GitHub Pages で動いており、次の3ページが存在します。**
  このリポジトリをそのまま `www.wize.uno` に割り当てると、**これらは消えます。**
  公開前に、同じリポジトリへ入れるのか、こちらへ移設するのかを決めてください。

  | パス | 内容 |
  |---|---|
  | `/advise/` | 有料相談の案内（5,000円/1回） |
  | `/freeadvise/` | 無料相談の案内 |
  | `/reserve.html` | 面談方法を選ぶ予約ページ。5つの選択肢から aitemasu.me の予約枠へ飛ぶ |

  ルート（`/`）だけが404の状態なので、**このサイトをルートに置けば3ページと共存できます。**
  予約の仕組み（aitemasu.me）は動作確認済みで、こちらで作り直す必要はありません。
- 記事一覧はブラウザ側で組み立てているため、`content/*.json` を更新しただけの状態では、検索エンジンのクロールが JavaScript 実行に依存します。気になる場合は管理画面の「HTMLを書き出す（サイト用）」で書き出したHTMLをコミットしてください（内容がHTMLに焼き付きます）。
